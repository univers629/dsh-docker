DSH 密钥管理面板

这里填的模型 API 密钥写进宿主上的 data/broker/keys.json（0600）并只交给 dsh-key-broker 容器。 DSH 容器拿到的永远是占位密钥和代理地址，所以容器里的 Agent 读不到真实密钥。保存后会顺便把供应商按 DSH 官方格式写进 settings.yaml，刷新 DSH 的 WebUI 就能在「设置 → 模型」里选模型。

固定请求头

代理转发时覆盖上去的头，例如 Codex 客户端要的 originator、version、User-Agent。认证类头不允许在这里出现：密钥由形态决定的那个头注入。

模型清单

写进 DSH 的模型 id，逗号或换行分隔（花名 id 照抄即可，例如 [蝶恋花]deepseek-v4-flash①）。DSH 内置目录里的上游（deepseek、openai、anthropic、google、nvidia 等）留空就沿用目录里的整份清单； 目录外的自建网关留空时，保存会自动向上游拉一次清单，拉不到才需要手写。

推理强度档位

留空 = 不声明。DSH 只对声明过档位的模型显示「推理强度」菜单，所以这一栏空着时那个下拉不会出现； 但给不吃 reasoning_effort 的模型声明档位，上游会直接返回 400，因此要按上游自己支持的填。 逗号分隔，可用：off、minimal、low、medium、high、xhigh、max （off 表示“不思考”，单独写它无效，至少再给一个档位）。
