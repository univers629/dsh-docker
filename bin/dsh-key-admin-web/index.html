DSH 密钥管理面板

这里填的模型 API 密钥写进宿主上的 data/broker/keys.json（0600）并只交给 dsh-key-broker 容器。 DSH 容器拿到的永远是占位密钥和代理地址，所以容器里的 Agent 读不到真实密钥。保存后会顺便把供应商按 DSH 官方格式写进 settings.yaml，刷新 DSH 的 WebUI 就能在「设置 → 模型」里选模型。

模型清单

左边勾上的模型才会保存进去，也才会写进 DSH 的 settings.yaml；取消勾选 = 从这份配置里去掉。 每个模型带着自己的调用能力和推理强度档位——这两件事本来就是逐模型的：同一个网关里 gpt-5 吃 reasoning_effort，图像模型不吃，所以没有"整条上游共用"的档位。 DSH 内置目录里的上游（deepseek、openai、anthropic、google 等）一个都不勾就沿用目录里的整份清单； 目录外的自建网关至少要留一个模型，一个都不留时保存会先向上游拉一次清单，拉不到 DSH 那边就不会多出这条供应商。

请求限额

数的是请求次数，不是 token 也不是金额：撞到上限时代理返回 429，每日配额按 UTC 零点清零。 0 = 不限，留空 = 沿用现值。按 token 或金额限额要逐家解析用量字段和维护价格表，这里不做—— 真要按钱卡住就去上游平台后台给这把密钥单独设额度。

容器出站策略

决定 dsh 容器出网时哪些域名放得过去。改完 5 秒内生效，不用重启容器。 模型请求不受影响：那条路走 dsh-key-broker，是另一个容器自己出网。

两种模式下都不会放松的部分：裸 IP 目标、localhost 与内网域名后缀、80/443 以外的端口、 解析结果落在内网的域名，一律拒绝。blocklist 只是把最后一道「域名判定」从「必须在白名单里」换成 「不在黑名单里」——它降低顺手滥用的概率，真正收口的只有 allowlist。

白名单

allowlist 模式下生效。支持 *.example.com（只能写最左边一级通配）。 Agent 要做网页搜索或读文档，就把那些域名加进来。

黑名单

blocklist 模式下生效。内置的是常见的一键公网隧道服务（它们能把容器里的端口发布到公网， 等于把密钥代理变成别人可用的免费网关）。不需要的可以取消勾选。
